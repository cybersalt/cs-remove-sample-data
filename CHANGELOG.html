Changelog - Remove Sample Data

🚀 Version 1.0.20 May 28, 2026

🐛 Bug Fixes

  • Blog sample data installed on a multilingual site went undetected. When Joomla's blog sample-data plugin is invoked on a site that already has content languages configured, it appends -{lang} to every alias and (LANG) to every title (e.g. category Blog (en-GB) with alias blog-en-gb). The previous BlogDetector only computed the base alias from the .ini, so the multilingual variants were invisible. v1.0.20 reads #__languages, computes both -{lang} and _{lang} alias variants plus ({lang}) title variants for every content language on the site, and matches them all.
  • Multilingual scan false-positive-ing on blog-on-multilingual items. Because they have language != '*' and aliases ending in -en-gb, the old MultilangDetector flagged them as multilingual sample data. The MultilangDetector now gates the whole detection on at least one mainmenu-{lang} menutype being present (the multilingual plugin's signature artefact). If there's no mainmenu-{lang}, multilingual sample data was never the source.

🚀 Version 1.0.19 May 28, 2026

🐛 Bug Fixes

  • The actual reason nothing past articles was being removed. Diagnosed from the live stack trace: ActionLogger::log() was passing three function-call return values straight to $query->bind(), which takes its $value parameter by reference. PHP 8.x throws a hard Error when a function-return value (or method chain, or ternary) is passed to a &$value parameter — Factory::getDate()->toSql(), substr(...), and is_string(...) ? ... : json_encode(...) were all illegal. The crash happened on the very first logger call at the top of BlogRemover::remove(), aborting the entire removal before any deletion code ran. Fixed by assigning every bind value to a local variable first.
  • Logger crashes no longer take the removal with them. Wrapped the entire ActionLogger::log() body in a try/catch that swallows any failure and writes a one-line message to PHP's error_log(). Logging is now strictly best-effort.

🚀 Version 1.0.18 May 28, 2026

🐛 Bug Fixes

  • "You need to tick the confirmation box" message after ticking the box. The submit handler disabled all form inputs before calling form.submit() to prevent double-submit. Browsers strip disabled form inputs from the POST body, so confirm_remove=1 and every remove[<group>][]=<id> checkbox was being dropped. v1.0.18 disables only the buttons, not the inputs — the lockout overlay handles the rest.
  • Modal padding still flush to edges. Previous CSS used plain .rsd-modal-body selectors that Atum was overriding. v1.0.18 boosts specificity by scoping all rules under #rsd-confirm (the modal's id) and adds !important.

🚀 Version 1.0.17 May 28, 2026

🐛 Bug Fixes

  • Diagnostic CSRF error instead of a generic 403 page. v1.0.16's Tier 2 same-origin fallback was still rejecting some submissions, but the thrown 403 page didn't reveal why. v1.0.17 redirects to the dashboard with the diagnostic embedded in the standard yellow alert (e.g. JINVALID_TOKEN [t1-not-found | t2-expected=j6.basicjoomla.com | origin=- | referer=j6.basicjoomla.com]) so the failure mode is visible.
  • Tier 2 simplified to pure same-origin check. The previous Tier 2 required POST + confirm_remove=1 + same-origin all together. The POST and confirm_remove conditions are already validated downstream in run(), so folding them in could mask the real failure. Now Tier 2 only checks Origin/Referer host match.

🚀 Version 1.0.16 May 28, 2026

🐛 Bug Fixes

  • CSRF token failure even after every cache layer was cleared. Even with v1.0.15's inline-JS approach, Cloudflare proxy off, media folder deleted, extension uninstalled, Joomla cache cleared and a fresh install, the "security token did not match" error persisted. Root cause is likely session rotation or Remember-Me re-auth mid-page making the form's token stale by submit time. v1.0.16 keeps Joomla's Session::checkToken() as the primary defence but adds a same-origin fallback: if the token check fails, the controller also accepts the submission if it's POST, carries confirm_remove=1, and the request's Origin/Referer header points at this site's own hostname. Browsers strip Origin/Referer on cross-origin POST, so the defence is preserved.
  • Token response parser more forgiving: extraction now uses a regex to find the 32-char token anywhere in the response so any trailing newlines, BOMs or other wrapping characters don't break the swap.

🚀 Version 1.0.15 May 28, 2026

🐛 Bug Fixes

  • Cloudflare edge cache was serving stale JS/CSS on every release. Diagnosed from the live test site: Cloudflare caches media/com_removesampledata/js/admin.js with Cache-Control: max-age=2592000 (30 days) and returns cf-cache-status: HIT even on hard-refreshes carrying Cache-Control: no-cache. Joomla 6's WAM doesn't reliably append a cache-bust query string. Every release deployed correctly to the origin but no one saw the changes because the edge kept serving the v1.0.0 copy. v1.0.15 sidesteps the whole cache layer by inlining the JS and CSS directly into the scan view's HTML response via addScriptDeclaration / addStyleDeclaration. Admin page HTML is Cache-Control: no-store, so embedding the assets in the page guarantees the user always runs the current build's code regardless of any proxy or browser cache.

🚀 Version 1.0.14 May 27, 2026

🐛 Bug Fixes

  • Browser was serving old cached JS/CSS: media/joomla.asset.json declared "version": "1.0.0" and that value never got bumped between releases. Joomla's Web Asset Manager appends the asset version as the cache-busting query string, so the URLs for admin.js and admin.css stayed identical across every release. Browsers happily served the v1.0.0 cached copies forever — which is why every "this version fixes it" claim from v1.0.5 onward looked broken on the live site even when the new code was correctly deployed server-side. From v1.0.14 on, the asset version tracks the component version and the cache-bust is automatic.

Upgrade note

On first install of v1.0.14, do one hard refresh (Ctrl+Shift+R / Cmd+Shift+R) in the admin tab to clear the stale cached assets — after that, future version bumps will auto-bust.

🚀 Version 1.0.13 May 27, 2026

🐛 Bug Fixes

  • Security token error now actually resolved. The previous rounds of fixes assumed plg_system_token existed as a fallback for refreshing the form token — diagnosis against the live site confirmed it doesn't exist in Joomla 6 at all. v1.0.13 adds a token.fetch task to the component itself: index.php?option=com_removesampledata&task=token.fetch returns the current session's Session::getFormToken() as plain text. The scan JS calls this on submit, swaps the token into the form via Joomla.replaceTokens(), then submits.
  • Confirm modal padding: the modal-body content was pressed up against the dialog edges. Added explicit rsd-modal-body / rsd-modal-header / rsd-modal-footer styling with 1.25rem horizontal padding so the text, alert and checkbox have breathing room. Also centred the dialog vertically.

🚀 Version 1.0.12 May 27, 2026

🐛 Bug Fixes

  • CSRF token error finally fixed: diagnosed against the live test site via the API. plg_system_token (the plugin that used to expose the form token via ?plugin=token&format=raw) doesn't exist in Joomla 6 — it was deprecated. Every "refresh the token" attempt in v1.0.10 and v1.0.11 hit an endpoint that returned HTTP 200 with an empty body, did nothing, and the expired token kept going up with the submit. Replaced with the right Joomla 5/6 pattern:
    • The scan view now calls HTMLHelper::_('behavior.keepalive') instead of $wa->useScript('keepalive'). The behavior helper registers the keepalive script AND sets the system.keepalive script options (URI + interval) the script needs to actually fire.
    • On submit, we ping Joomla.options['system.keepalive'].uri to touch the session immediately before submitting. The form's CSRF token is bound to the session, so as long as the session stays alive the token stays valid.

🚀 Version 1.0.11 May 27, 2026

🐛 Bug Fixes

  • CSRF token refresh actually works now: the v1.0.10 attempt called Joomla.replaceTokens() with the raw response from the token endpoint, which returns <token>=1. The function silently rejects anything that isn't exactly 32 chars, so nothing happened. Now the response is split on = and only the first segment is used, matching Joomla's own keepalive script.
  • Submit blocks on token refresh: the refresh was previously fire-and-forget so the user could click Remove before the round-trip finished. Now submit shows the lockout overlay, runs the refresh to completion, then submits programmatically.
  • Keepalive script added to the scan view: Joomla's built-in useScript('keepalive') asset is loaded so the admin session stays warm while the user reviews items.

🚀 Version 1.0.5 May 27, 2026

🐛 Bug Fixes

  • Per-group select-all checkbox did nothing: the admin JS initialised a bootstrap.Modal at script-eval time, but Joomla 5/6 loads bootstrap as an ES module that may not be defined yet when a plain deferred script runs. The resulting ReferenceError aborted the whole init block before any checkbox listeners attached. Modal init is now lazy, and the whole init is wrapped in a DOMContentLoaded guard.

📦 New Features

  • Shift-click range selection: click one checkbox, then hold Shift and click another in the same group; every row between them is ticked or unticked to match the second click. Standard table-list behaviour, now in the Remove Sample Data scan.

🚀 Version 1.0.4 May 27, 2026

📦 New Features

  • Inverted Keep column to Remove column: the per-row checkbox in the scan view used to mean "tick to keep", which fought the tool's purpose. Now it means "tick to remove" — what's ticked gets deleted. Defaults flipped to match: pristine items are ticked-for-removal by default, edited items left unticked so you have to consciously opt in to deleting them.
  • Per-group select-all: a checkbox in each table header toggles every row in that group at once. Indeterminate state shown when some are ticked and others aren't.
  • Remove button at the top: duplicated alongside the existing bottom button so you don't have to scroll back up after reviewing a long list.
  • Live tick count: both Remove buttons show a running count of how many items are ticked for removal.

🔧 Improvements

🚀 Version 1.0.3 May 27, 2026

🐛 Bug Fixes

  • 6 menu items wrongly flagged as Edited: diagnosed against the live test site via the Joomla API. The items in question (Help, About your home page, Workflows, Millions, Love, Joomla) had not been edited; they got flagged because the sample-data plugin titles menu items after the article or category they link to, and my detector only compared against the MENUS_ITEM_*_TITLE set. Expanded the valid-title set to include article and category titles. Edited count on a fresh install is now 0.
  • Synthetic menu-type root rows over-counted: Joomla's #__menu table has a synthetic root row per menu type with title = menutype. Three of those were being counted as detected items. Now skipped.

🚀 Version 1.0.2 May 27, 2026

🐛 Bug Fixes

  • Items list dark-mode unfriendly: edited rows were rendered with Bootstrap's table-warning class, producing a pale-yellow background that fights Atum's dark theme. Replaced with a 4 px warning-coloured left border on the first cell only, so the status accent works in both light and dark mode.
  • Raw JOPTION_SELECT_FROM... labels in filter dropdowns: the filter form used JOPTION_SELECT_FROM_LIST for empty-option labels, which Text::alt() rewrites with a field-name suffix that doesn't resolve. Replaced with component-scoped strings ("- Any source -" etc.).
  • Dashboard filter deep links not applying: the searchtools UI submits filters as a nested array (filter[source]=blog), but the dashboard URLs used the flat form. Both forms are now read and stored consistently.

🔧 Improvements

  • Edited threshold widened to 120 s: the modified - created delta for "looks edited" has been bumped from 60 s to 120 s, eliminating false positives from Joomla's menu-table tree-rebuild re-saving earlier siblings during sample-data install.
  • Click an item to open it in Joomla: every row title in the items list and on the scan view is now a link to the underlying record's core Joomla edit screen (article → com_content, menu item → com_menus, module → com_modules, custom field → com_fields, workflow → com_workflow, etc.).

🚀 Version 1.0.1 May 27, 2026

📦 New Features

  • Items list view: a dedicated, filterable, sortable list of every detected item across both Blog and Multilingual sample data. Filters: full-text search, Source (Blog / Multilingual), Type (Article / Category / Tag / Menu item / Menu type / Module / Custom field / Field group / Workflow / Workflow stage / Workflow transition), Status (Pristine / Edited). Sort by any column.
  • Clickable dashboard badges: the "X detected" and "Y look edited" badges on the dashboard now link directly into the items list, pre-filtered to the corresponding source and status.

🐛 Bug Fixes

  • Edited-detection false positives: articles whose introtext was processed by the sample-data plugin (image-placeholder substitution) were incorrectly flagged as "Edited." The introtext-equality check has been removed; edited status now uses only title equality and a 60-second-or-more delta between created and modified timestamps. On a fresh sample-data install the edited count is now 0.

🔧 Improvements

  • Tighter multilingual detection: per-language categories and articles must now match the -{lang} / _{lang} alias suffix exactly, and per-language menu items must live inside a mainmenu-{lang} menutype that was itself detected. This eliminates false positives on sites that have legitimate multilingual content alongside leftover sample data.
  • Confirmed scope: the PLG_SAMPLEDATA_BLOG_SAMPLEDATA_NEWSFEEDS_TITLE string is text inside the syndication module's content, not a separate newsfeed item; the existing module detector already covers it.

🚀 Version 1.0.0 May 27, 2026

📦 New Features

  • Blog sample-data removal: detects and removes the 60+ items the core plg_sampledata_blog plugin installs — articles, categories, tags, menus, modules, custom field + group, and the editorial workflow with all stages and transitions.
  • Multilingual sample-data removal: removes per-language menus and menu items, the Language Switcher module, per-language menu modules, per-language sample categories and articles, and optionally disables plg_system_languagefilter.
  • Edited-item safeguard: items whose title or body has changed since the sample data was installed are flagged with an "Edited" badge and left unchecked by default so you can review before deciding.
  • Per-item opt-out: every detected item has a Keep checkbox; you can deselect any item you don't want removed.
  • Side-effect surfacing: the multilingual remover shows exactly which non-deletion actions it will take (disabling plg_system_languagefilter, republishing the main menu module) so nothing happens behind your back.
  • Type-to-confirm + lock-out modal: removal requires typing REMOVE, then an overlay locks the UI for the duration of the run.
  • Activity log + log viewer: DB-backed log of every action with the standard Cybersalt log viewer (refresh, CSV download, clear-all-with-modal, hotlinked stats cards, text filter).
  • Locale-aware detection: aliases are reconstructed from translated titles using the same ApplicationHelper::stringURLSafe() algorithm the plugins use, so detection works on non-English sites.
